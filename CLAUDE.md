## Architecture

**Workout Week Manager** is a client-side-only PWA for planning and tracking weekly workouts. No backend — all data lives in `localStorage`. The app is installable on iOS Home Screen and works offline via a service worker generated by `vite-plugin-pwa`.

### Data flow

`useWeek` hook (src/useWeek.ts) is the single source of truth. It holds the current week's state and exposes all mutations (add/edit/delete workouts, toggle completion, copy week, navigate weeks). Every mutation persists to `localStorage` via `src/storage.ts`.

### Data model (src/types.ts)

- **WorkoutType**: `'running' | 'indoor-bike' | 'street-workout' | 'strength'`
- Running and indoor-bike workouts have an optional `distance` (km) field
- Each **Workout** belongs to a day (0=Mon..6=Sun), has a type, exercises list, and completed flag
- **WeekData** keyed by ISO week ID (e.g. `"2026-W45"`)
- `storage.ts` includes a migration that backfills `type: 'strength'` for data saved before types were added

### Week ID format

ISO week strings like `"2026-W45"`. All week math (navigation, copy-to-next) goes through `src/weekUtils.ts` which converts between week IDs and dates.

### Views

The App component (src/App.tsx) switches between two view modes:
- **Calendar view** — 7-column grid (DayColumn → WorkoutCard)
- **List view** — vertical scroll grouped by day (ListView → WorkoutCard)

WorkoutCard is shared between both views. Modals (WorkoutModal, ProgressReport) are rendered at the App level.

### Styling

Single CSS file (src/index.css) with CSS custom properties for theming. Dark theme, mobile-first responsive breakpoints at 900px and 1200px. iOS safe area insets are handled.

### TypeScript strictness

`noUnusedLocals` and `noUnusedParameters` are enabled — unused variables/imports will fail the build.
